# 平台消费数据可信度

评估重点平台消费数据（智能眼镜、心电监护仪、运动相机等增长指标）的覆盖、口径与统计可用范围，
保证平台覆盖范围、类目映射与促销口径变化时汇总结果仍可追溯、可比较。

## 业务规则与实现映射

| 业务要求 | 实现 |
| --- | --- |
| 管理平台数据贡献方 | `fixtures/platforms.json`：平台名录、覆盖类目、接口版本、角色账号（不含凭据） |
| 每次报送保存六要素：样本覆盖、类目字典、去重方法、退款处理、价格口径、质量声明 | 批次台账 `methodology` 六字段 + 质量声明，缺任一要素即 blocker（`src/validation.py`） |
| 迟报、撤回、接口改版、历史回补只生成新批次 | append-only 台账（`src/ledger.py`）：`late/withdrawal/api_change/backfill` 均为独立批次，沿 `supersedes` 留痕，历史批次不被覆盖 |
| 撤回数据不得使用；回补替代初报 | `effective_batches()` 排除撤回批与被回补替代批；撤回批无观测 |
| 异常波动先核查，不直接写入公开统计 | `src/anomaly.py`：环比阈值 30% + 同口径历史 z 分数双判，命中即隔离；接口改版批次不参与环比 |
| 自动校验 | 六要素完整性、映射表与分类表一致性、未映射占位（000000 阻断）、观测期间、退款超额、覆盖缺口、口径断点 |
| 质量评分 | `src/quality.py`：六维评分（对应六要素）、逐维扣分原因、A/B/C/D 等级与置信说明 |
| 问题工单 | `src/tickets.py`：校验问题与异常自动开工单，支持核查/关闭流转 |
| 平台只能查看自身问题 | 工单与血缘均按角色鉴权：`platform` 仅见本平台，越权抛 `PermissionError` |
| 统计人员可比较来源差异 | `compare_sources()`：同期同类目各来源数值、评分、审批范围、批次链与价格/退款/去重口径差异 |
| 可用范围审批 | `src/approvals.py`：内部参考 < 趋势比对 < 公开统计三级；系统计算最高可支持范围，审查不得超范围批准，批准可撤回 |
| 采用指标时给出血缘与置信说明 | `src/lineage.py`：有效批次、撤回/回补批次链、六要素快照、类目映射、质量评分、未闭工单、断点、审批、可采用结论 |

### 隔离与采用门槛

- 存在 blocker 或质量 D：任何用途均不支持；
- 异常核查未关闭 / 严重工单未关闭：仅内部参考；
- 质量 C、有重要工单、或存在未回溯口径断点：最高趋势比对；
- 质量不低于 B 且无上述限制，方可在有效审批覆盖下写入公开统计；
- 审批有效期、条件与撤回记录（如 P-GOLIVE 接口改版后公开批准被撤回）均留痕。

## 目录说明

- `contracts/domain.schema.json`、`contracts/submission.schema.json`：领域资料与报送批次契约。
- `fixtures/`：标准分类表、平台与账号目录、append-only 批次台账（含迟报/撤回/接口改版/回补/异常尖峰样例）、审批留痕、公开领域样例。
- `src/`：
  - `records.py` 共享资料读取；`catalog.py` 分类目录；`directory.py` 平台与账号；
  - `ledger.py` 批次台账；`validation.py` 自动校验与口径断点；`anomaly.py` 异常隔离；
  - `quality.py` 质量评分；`tickets.py` 工单与权限；`approvals.py` 范围审批；
  - `lineage.py` 血缘说明与来源比较；`service.py` 串接全流程的服务门面。
